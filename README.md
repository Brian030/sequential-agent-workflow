# 循序子 Agent 工作流程

這個 Codex skill 會在**同一個 Codex 任務**中，依 Markdown 文件列出的順序逐一建立子 agent。主 agent 等待每個子 agent 完成並檢查指定的完成標準；全部通過才開始下一項。若失敗或無法驗證，流程立即停止，並在目前的 Codex 任務說明原因。

## 檔案

| 檔案 | 用途 |
| --- | --- |
| `SKILL.md` | 執行、驗收與停止規則。 |
| `workflow.md` | 可直接修改的預設工作流程範本。 |
| `agents/openai.yaml` | Codex 中顯示的 skill 名稱與啟動提示。 |

修改來源的 `workflow.md` 後，不必重新安裝。

## 快速開始

1. 開啟來源資料夾的 `workflow.md`，填入工作流程名稱、每項任務的內容與完成標準，並為每項任務指定模型和推理程度。刪除或改寫「請填寫」「請描述」等範例文字。
2. 依需要增加或刪除 `## 任務 N：名稱` 區塊，讓編號依執行順序排列。完成標準應能根據產出、檔案、資料或測試結果檢查。
3. 在 Codex 桌面版開啟一個任務，輸入：

   ```text
   使用 $sequential-agent-workflow 執行預設工作流程。
   ```

沒有指定檔案路徑時，skill 會讀取**與 `SKILL.md` 同目錄**的 `workflow.md`。附帶的 `workflow.md` 是未填妥的範本，填寫前不會啟動子 agent。

## 使用其他工作流程檔

工作流程可以是 Codex 可讀取的其他 Markdown 檔案，檔名不必是 `workflow.md`。啟動時明確給出路徑即可；跨資料夾時建議使用絕對路徑。

```text
使用 $sequential-agent-workflow 執行 E:\OpenAI\Projects\report-flow.md。
```

指定路徑會優先於預設的 `workflow.md`。不同專案可以各自保存一份流程檔，不需要修改 `SKILL.md`。

## 工作流程格式

每個任務區塊都需要下列欄位；可參照附帶的 `workflow.md`：

```markdown
## 任務 1：任務名稱

模型：`gpt-6-sol`
推理程度：`medium`

### 任務內容

描述這位子 agent 要完成的工作。

### 完成標準

- 寫出可逐項檢查的條件。

### 交付成果

- 可選填預期的檔案或文字成果。
```

模型與推理程度只是範例。執行前，主 agent 會檢查所有任務的必要欄位，以及指定模型和推理程度在目前 Codex 環境中是否可用；設定不符時會指出問題並停止，不會自行替換。

## 執行與驗收

- 每項任務使用一位新子 agent，並以 `fork_turns: "none"` 建立獨立的對話脈絡。主 agent 只交付該階段所需的任務、標準及前階段已驗收的相關成果。
- 主 agent 逐項檢查完成標準；子 agent 自稱完成，不等於通過驗收。
- 任一標準未通過、無法驗證、子 agent 執行失敗或缺少必要工具時，主 agent 不啟動下一位子 agent，也不自行重試。通知會出現在目前的 Codex 任務中，包含停止階段、原因、檢查依據及已有成果。
- 所有階段通過後，主 agent 回報完成的任務與最終交付成果。

這套流程由 Codex skill 指導主 agent 執行；它不是程式層級的強制驗收閘門。
